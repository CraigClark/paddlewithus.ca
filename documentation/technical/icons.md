# Icon system

How icons get from the theme into menu links, view fields, and content. Covers the architecture, plus the day-to-day workflows for adding more icons.

## Overview

Three layers, all local — no CDN at runtime.

| Layer | What it does | Where |
|---|---|---|
| `material_icons` contrib module | Provides the `.material-icons` CSS class. Originally loads the webfont from Google Fonts; we override it to load locally. | `html/modules/contrib/material_icons/` |
| `ui_icons` + `ui_icons_menu` contrib modules | Adds an icon picker to the menu link form; preprocesses menus to inject icon markup into `item.title`. | `html/modules/contrib/ui_icons/` |
| `daisyui_ext` theme | Hosts the local Material Icons webfont, a curated list of icon names exposed to the picker, and a custom SVG sprite for non-Material icons (brand logos). Registers both as `ui_icons` packs. | `html/themes/custom/daisyui_ext/` |

The CDN-to-local swap lives in **`picc_ext`** so it applies on admin pages too (where the Gin theme is active, not `daisyui_ext`).

## Where files live

```
html/themes/custom/daisyui_ext/
├── fonts/
│   └── MaterialIcons-Regular.woff2          # the font itself (128 KB, ~2,000 glyphs)
├── css/
│   └── material-icons.css                    # @font-face + .material-icons class
├── icons/
│   ├── material-icons.codepoints             # picker allowlist (one icon per line)
│   └── default/                              # source SVGs for the custom sprite
│       ├── facebook.svg
│       ├── instagram.svg
│       └── …
├── dist/assets/
│   └── default-icons.svg                     # built sprite (regenerated by npm run build)
├── daisyui_ext.icons.yml                     # ui_icons pack definitions
└── daisyui_ext.libraries.yml                 # material-icons library entry
```

Plus:
- `html/modules/custom/picc_ext/picc_ext.module` — `picc_ext_library_info_alter()` swaps `material_icons/baseline` to load locally; `picc_ext_link_alter()` keeps menu titles visible on the admin menu overview.

## The two packs

Both appear in the same picker on menu link forms (and any other `ui_icons` widget). The search field filters across both.

### `material_icons`

Font-glyph icons drawn from the locally-hosted Material Icons baseline webfont. The full font ships ~2,000 glyphs, but only the names listed in `icons/material-icons.codepoints` show up in the picker. That deliberate gate keeps the dropdown manageable and predictable.

Defined in [daisyui_ext.icons.yml](../../html/themes/custom/daisyui_ext/daisyui_ext.icons.yml):

```yaml
material_icons:
  enabled: true
  label: "Material Icons"
  extractor: font
  config:
    sources:
      - "icons/material-icons.codepoints"
  template: '<span class="material-icons" aria-hidden="true">{{ icon_id }}</span>'
  preview: '<span class="material-icons" style="font-size: {{ size|default(32) }}px;" aria-hidden="true">{{ icon_id }}</span>'
```

### `daisyui_ext_icon_pack`

Custom SVGs from a Vite-built sprite. Used for brand logos and anything else not in the Material set. Each `.svg` dropped into `icons/default/` becomes a `<symbol>` in the built sprite.

## Adding a new Material Icon to the picker

Use this when the icon exists in Google's Material Icons baseline set and you want authors to be able to pick it from menus.

1. **Verify the icon name exists.** The authoritative list is the codepoints file Google publishes. The whole list (~2,000 names) is at `/tmp/material-icons.codepoints` if you've recently set up, or pull fresh from https://raw.githubusercontent.com/google/material-design-icons/master/font/MaterialIcons-Regular.codepoints. Each line is `icon_name codepoint_hex`.

2. **Append to** [icons/material-icons.codepoints](../../html/themes/custom/daisyui_ext/icons/material-icons.codepoints):

   ```
   bookmark e866
   ```

   The codepoint hex isn't used in the template (we use the ligature name via `{{ icon_id }}`), but the line must have two whitespace-separated values or the extractor skips it.

3. **Clear cache**: `drush cr`.

4. **Verify** in any menu link form: search for the new name in the icon picker. It should render the actual glyph in the dropdown.

No `npm run build` needed — the font file already contains every baseline glyph; the codepoints file just controls discovery.

## Adding a new custom or brand SVG icon

Use this when the icon isn't in Material Icons (brand logos, custom symbols, etc.).

1. **Source the SVG.** Good sources:
   - [Simple Icons](https://simpleicons.org) — brand logos, CC0 license.
   - [Material Symbols](https://fonts.google.com/icons) — newer Material set, Apache-2.0 (export individual SVGs).
   - Anywhere else with a compatible license.

2. **Clean it up.** The Vite SVG sprite plugin keeps SVG content intact, but for consistency strip explicit dimensions and use `fill="currentColor"` so the icon inherits text color:

   ```svg
   <svg viewBox="0 0 24 24" xmlns="http://www.w3.org/2000/svg">
     <path fill="currentColor" d="…"/>
   </svg>
   ```

3. **Drop it** in [icons/default/](../../html/themes/custom/daisyui_ext/icons/default) with a kebab-case filename (the filename becomes the icon ID with a `default-` prefix — e.g. `linkedin.svg` → `default-linkedin`).

4. **Rebuild the sprite**:

   ```bash
   cd html/themes/custom/daisyui_ext
   npm run build
   ```

5. **Clear cache**: `drush cr`.

6. **Verify** in the picker — search by filename minus the prefix (e.g. "linkedin").

The built sprite at `dist/assets/default-icons.svg` is committed to the repo, so other deployments pick up the new icon automatically.

## Adding an icon to a menu link

This is the day-to-day workflow once the icon is in a pack.

1. Edit any menu link at `/admin/structure/menu/manage/<menu>` → **Edit**.
2. Under **Link icon**, type to filter. Pick the icon.
3. Under **Link icon settings**, choose a display position:
   - `Before` — icon then title.
   - `After` — title then icon.
   - `Icon only` — icon replaces the title visually.
4. Save.

## Accessibility: icon-only menu links

`ui_icons_menu`'s `icon_only` display mode replaces the visible title with just the icon. The `<a>` element ends up with no accessible name — screen readers announce nothing useful.

The standard fix is to add an `aria-label` to the link. The `menu_link_attributes` module exposes this as a configurable attribute:

1. On the menu link edit form, open **Attributes**.
2. Set **ARIA label** to the accessible name (e.g. `Facebook`).
3. Save.

The output is a link with `aria-label="Facebook"` and an SVG/glyph with `aria-hidden="true"` — the WCAG-recommended pattern for icon-only links.

If you ever need to disable or expose a different attribute, the config is at `/admin/config/menu_link_attributes/config` or in `menu_link_attributes.config` via drush.

## The CDN-to-local override (for maintainers)

`material_icons` ships expecting to load the webfont CSS from Google Fonts:

```yaml
# html/modules/contrib/material_icons/material_icons.libraries.yml
baseline:
  css:
    theme:
      //fonts.googleapis.com/icon?family=Material+Icons: { type: external }
```

We replace that library's `css.theme` array with our local file in [picc_ext.module](../../html/modules/custom/picc_ext/picc_ext.module):

```php
function picc_ext_library_info_alter(array &$libraries, string $extension): void {
  if ($extension !== 'material_icons' || !isset($libraries['baseline'])) {
    return;
  }
  $libraries['baseline']['css']['theme'] = [
    '/themes/custom/daisyui_ext/css/material-icons.css' => [],
  ];
}
```

This lives in `picc_ext` rather than the theme because `libraries-override` in `daisyui_ext.info.yml` only takes effect when daisyui_ext is the active theme. On admin pages Gin is active, so a theme-level override wouldn't apply there — and the icon picker needs to render glyphs on admin pages.

Other Material Icons families (`outlined`, `two-tone`, `round`, `sharp`, `symbols__*`) are still wired to load from the CDN in `material_icons.libraries.yml`. They don't actually attach unless added to `material_icons.settings.families` config, which is currently just `[baseline]`. If you want to add another family, you'd need to:
1. Download its woff2 to `daisyui_ext/fonts/`.
2. Add `@font-face` + class to `css/material-icons.css` (or a sibling file).
3. Extend `picc_ext_library_info_alter()` to override that family's library too.

## The admin-overview title fix

`ui_icons_menu_link_alter()` mutates `$variables['text']` on every rendered link with an icon. On the admin menu overview at `/admin/structure/menu/manage/<menu>`, that turns icon-only links into a row showing only the icon — you can't tell which link is which.

[picc_ext.module](../../html/modules/custom/picc_ext/picc_ext.module) fixes this with a `hook_link_alter` that runs before ui_icons_menu's (alphabetical module order). On admin routes it pre-sets `ui_icons_processed` on the URL options, which causes ui_icons_menu's alter to bail early. Front-end rendering is unaffected because that path uses `hook_preprocess_menu`, not `hook_link_alter`.

## Pitfalls

- **Don't put the picker's allowlist in the theme's `info.yml` libraries-override.** Theme-level overrides only fire when the theme is active. Picker glyphs need to render on admin pages — use the module-level hook.
- **`daisyui_ext_icon_pack` had a stale source path** in the starterkit (`dist/default-icons.svg` instead of `dist/assets/default-icons.svg`, which is where Vite actually emits). Fixed in commit `0a99a2c`. If you ever see "0 icons" for that pack again, that's the first place to check.
- **There is no FontAwesome here.** Some legacy guides or copilots will suggest installing `drupal/fontawesome` — we deliberately don't, because adding it overlaps with what ui_icons + material_icons already provide. Brand logos go in the custom SVG sprite.
- **Rebuild only the sprite, not the codepoints.** Material Icons changes don't need `npm run build`; only changes under `icons/default/` do.
